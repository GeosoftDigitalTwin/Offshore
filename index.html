GeoSoft® Structural Digital Twin

From seeing the asset to understanding, verifying and managing it.

The Structural Digital Twin extends GeoSoft's 3D, point cloud, BIM and GIS environment into a full engineering platform. Click any leg, brace or joint and see what it is, what loads it, how it behaves, whether it is safe, how it has changed and what the engineer should do next, with the evidence behind every answer.

Positioning: the structural intelligence layer for the physical asset. Not only analysis software, not only a digital twin, not only a 3D viewer, but all three joined with monitoring, inspection and AI.

The success test

An engineer selects any structural component in the 3D scene and answers all of these from one interface. If the platform answers them reliably, transparently and traceably, GeoSoft has moved from a 3D twin to a structural engineering twin.

  • What is it, and what is it made of?
  • What loads it?
  • How is it behaving: stress, strain, deflection?
  • What is its utilization, and does it satisfy the code?
  • Which sensors monitor it, and which defects are recorded?
  • How has it changed over time?
  • What is its current risk?
  • What happens under a changed scenario?
  • What maintenance or strengthening is required?
  • What evidence supports that conclusion?

      Load engine and load combination engine

      Loads are stored as objects attached to the twin, not as numbers inside a solver file. Select an object in 3D and follow the chain from applied load to structural response.

      Load families supported

      Permanent

      Self-weight, dead load, fixed equipment, finishes, hydrostatic where permanent.

      Variable

      Live and imposed load, equipment and machinery, crane loads, vehicle loads, pipe loads, construction and temporary loads.

      Environmental

      Wind, seismic, snow where applicable, thermal, pressure, equipment vibration.

      Marine and offshore

      Hydrostatic, hydrodynamic, wave, current, buoyancy.

      Accidental

      Impact, collision, blast where appropriate and legally permissible, accidental and exceptional loads.

      Combination builder

      Coefficients are never hard-coded. Each combination is generated from a versioned code implementation and carries its code, edition, clause, factors, participating cases, assumptions, units, analysis type and status. Pick a design situation.

      Factors are ISO 19902-style values for illustration and must be checked against the edition and operator requirements the project uses. The platform stores the edition and any operator amendments as part of the code version.

      Analysis engine and result visualization

      GeoSoft connects to professional solvers rather than replacing them on day one. The twin generates the analysis model, sends it to the right solver, stores results with full provenance and draws them back onto the 3D scene.

      Three analysis speeds

      Tier 1 · Instant

      AI surrogate or reduced-order model. Used for interactive what-if screening. Never final design.

      Tier 2 · Fast

      Simplified physics. Used for engineering scenario screening, like the jacket lab in this page.

      Tier 3 · High fidelity

      Full FEM in a validated solver. Used for final engineering analysis and sign-off.

      Four kinds of number, never confused

      • Solver result Full-fidelity analysis output.
      • AI prediction Surrogate estimate with confidence.
      • Engineering estimate Hand or simplified calculation.
      • Measured Sensor-derived value.

      Each kind has its own label, pattern and colour in the 3D scene and in reports, so the meaning survives even in greyscale print.

      Dynamic behaviour: mode shapes

      A jacket sways like a cantilever, so uniform cantilever eigenfunctions are used here. Frequency ratios follow β² (1 : 6.27 : 17.55). Illustration only.

      Solver strategy

      • Native lightweight engine for beams and frames in the browser and for instant feedback.
      • Open-source FEM integrations such as OpenSees, CalculiX and Code_Aster, each subject to licence and validation review.
      • Commercial solver APIs where clients already rely on them, through the same analysis model generator.
      • Cloud, HPC and GPU solvers for large meshes, time histories and many scenarios.
      • AI surrogates for fast approximate prediction, always labelled as predictions.

      Design code engine and adequacy

      Not one monolithic code checker. A versioned engine where every check traces from code family to clause to formula to intermediate values, so the engineer can inspect exactly what was calculated.

      Code hierarchy

      1. Code familyISO 19902 (API RP 2A as alternative)
      2. EditionProject edition, e.g. ISO 19902:2020 (example)
      3. SectionStrength of tubular members
      4. ClauseCombined axial compression and bending
      5. Formulaσc/fc,d + Cmσb/[fb,d(1 − σc/fe,d)] ≤ 1
      6. ParametersD, t, K, L, fy, γR,c, γR,b, Cm
      7. ApplicabilityD/t within code limits; no dent or hydrostatic pressure
      8. Calculationlinked to lab
      9. Result
      10. EvidenceModel AM-J01 v1, run ID, inputs hash

      The same structure holds for any code, for example AISC 360-22, Chapter E, Section E3 for building columns. Compliance is never claimed until the implementation is independently verified.

      As-designed vs as-built

      Surveys are compared with design and as-built models to find out-of-verticality, missing or extra members, dents, dimensional deviation, scour, settlement and tolerance issues. Each deviation is then checked for structural effect, not just reported as geometry.

      Event engine

      After a storm, earthquake, vessel collision, dropped object, fire or abnormal load, the platform runs a defined response. Start a simulated event to watch the sequence.

      AI, prediction and risk

      Physics-based model plus sensor data plus AI, never AI alone. Physics constrains and validates the AI; AI speeds up prediction, anomaly detection, calibration and optimization. AI can identify and prioritise, but it does not declare a structure unsafe.

      Anomaly detection with change-point

      Expected band from the physics model with seasonal marine growth and tide. The change-point marks where the measured first sway frequency leaves the band. Method candidates: statistics, time-series models, change-point detection, Bayesian inference, physics-informed ML.
